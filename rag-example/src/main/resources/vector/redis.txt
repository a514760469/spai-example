Redis为什么快？
Redis 快，不是靠某一个神秘技术，而是多种设计共同作用的结果。核心可以概括为：数据在内存、核心命令单线程、IO 多路复用、高效数据结构、简单协议和合理编码。

第一，纯内存操作。Redis 的数据主要放在内存里，读写不经过磁盘。内存随机访问是纳秒级，磁盘是毫秒级，差了好几个数量级。持久化虽然会碰磁盘，但通常是后台子进程或异步刷盘，不直接拖慢主流程。

第二，核心命令执行是单线程。单线程避免了多线程上下文切换、锁竞争、死锁和并发修改数据结构的问题。Redis 的瓶颈通常在网络和内存，不在 CPU，所以单线程反而更简单高效。注意，Redis 不是完全单线程。6.0 以后网络 IO 可以多线程，持久化、异步删除、集群等也有后台线程或子进程，但命令执行主流程仍然是单线程。

第三，IO 多路复用和事件驱动。Redis 在 Linux 上用 epoll，在 BSD 和 macOS 上用 kqueue，也支持 select 等。一个线程可以管理大量 socket 连接，事件到达才处理，非阻塞，不需要为每个连接开一个线程。这样高并发下资源消耗低，上下文切换少。

第四，高效的数据结构。Redis 自己实现了 SDS 动态字符串，O(1) 获取长度，二进制安全，预分配减少内存重分配。哈希表平均 O(1) 查找。跳表支持范围查询，实现比平衡树简单。压缩列表、listpack、quicklist、intset 等紧凑编码节省内存，对 CPU 缓存更友好。Redis 还会根据元素数量和大小自动切换编码。

第五，渐进式 rehash。Redis 的全局哈希表在扩容或缩容时，不是一次性迁移所有数据，而是分多次逐步搬迁。这样避免长时间阻塞主线程。

第六，简单协议 RESP。Redis 协议简单，解析快，客户端实现也容易。Pipeline 可以批量发送命令，减少网络往返时间。Lua 脚本也能减少多次网络交互，但慢脚本会阻塞主线程。

第七，内存分配器 jemalloc。jemalloc 在内存分配和释放上效率较高，能减少内存碎片，提高 Redis 在频繁增删改查下的性能。

第八，没有复杂 SQL 解析和事务锁开销。Redis 命令直接操作数据结构，不像关系数据库那样需要解析 SQL、生成执行计划、维护复杂锁和磁盘索引。

第九，多线程 IO 提升网络吞吐。Redis 6.0 以后，网络读写可以多线程并行处理，但命令执行仍然单线程。这样既保留单线程执行命令的简单性，又提升网络密集型场景的吞吐。

第十，快的前提是合理使用。如果出现大 key、keys、hgetall 大对象、lrange 大范围、flushall、慢 Lua 脚本，单线程会被阻塞，Redis 也会变慢。持久化 fork、内存不足触发交换、网络延迟、CPU 饱和也会影响性能。

总结：Redis 快，主要是内存操作、单线程命令执行、IO 多路复用、高效数据结构、渐进式 rehash、简单协议和 jemalloc 共同作用的结果。它不是绝对快，合理使用和避免慢命令同样重要。
